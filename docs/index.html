Architecture

CLOUD RUN NEVER
TOUCHES FIRESTORE.

A deliberate split: auth and data persistence happen client-side, gated by Firestore security rules. Cloud Run's only job is holding the Gemini key and authenticating the caller before spending it.

personal-gemini-journal / server.js · public/index.html
INPUT · Firebase ID token + journal message
Stage 01
🔐

Verify

Cloud Run verifies the Firebase ID token via Admin SDK before spending anything.
firebase-admin
Stage 02
🔑

Fetch Key

Gemini API key fetched from Secret Manager at runtime — never in the client bundle.
Secret Manager
Stage 03
💬

Call Gemini

Multi-turn chat, or a structured-JSON RDI scoring call — two routes only.
Gemini 3.6 Flash
Stage 04
🗄️

Client Writes

Result returns to the browser, which writes it to Firestore directly — rule-gated, not server-gated.
request.auth.uid == userId
firestore.rules: allow read, write: if request.auth != null && request.auth.uid == userId; — default-deny on everything else.
